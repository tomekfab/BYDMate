Unified style: the same 360–380px width, 12×16 padding, and 12 border radius, with a 1.5dp border in the card theme accent colour. Border colour semantics: parking — orange; battery — green/yellow/red by worst-of; insights — blue.

Trendy
Wykresy pojawią się po pierwszym ładowaniu i zebraniu ≥3 pomiarów. Snapshoty DiPlus są zapisywane niezależnie od autoservice — ten blok będzie działać dla wszystkich.
Section A (period) is available to everyone and is calculated from our charging database. Section B (Lifetime) is available only with autoservice. Section C (Trends) is available to everyone (DiPlus snapshots) but requires ≥3 measurements.
Snapshot trigger: when the car is detected as waking, the app requests from DiPlus cell V min/max, battery temperature, 12V, and SoC, then writes one record to battery_snapshot. It triggers on: (a) service start after sleep, (b) detected end of charging (SoC increased), (c) the first start of the day.

Change summary

1. Dialog unification: Battery / Parking / AI Insights use the same behaviour and positioning (CenterStart; tap inside = close).
2. Battery Health expanded dialog simplified: only a “Now” block (DiPlus, for everyone) and a “Lifetime” block (autoservice or placeholder). No charts and no calculated SoH.
3. /Charging right column: 3 sections — Period (everyone), Lifetime (autoservice), Trends (snapshots after waking).
4. ChargeEdit: SOC is the main input; kWh is computed read-only when SOC values are filled. DC fallback without SOC.
5. Backend bugfix: Fix the DiPlus snapshot write path in the battery_snapshot table — cell Δ/live temperature arrives now, but is not persisted, so the “Trends” charts are empty.
